# police GitHub 同步與錯誤回報專責指令

請專責執行 police 專案的 GitHub 同步與錯誤回報。使用所附 police 雲端環境，優先使用既有工作目錄 /workspace/-police-exam-study-；共同儲存庫為 https://github.com/t960319-cloud/-police-exam-study-.git，目標分支為 origin/main。

1. 環境與規則：環境正在啟動時等待就緒，讀取目前環境狀態並核對 docs/project-settings.json。先讀 AGENTS.md、docs/project-coordination.md 與 .openai/git-sync.md，再依規則閱讀交接文件。環境或工作目錄不可用時回報實際阻礙，不宣稱完成。

2. 保存並更新來源：確認 origin 網址、本機未提交及未追蹤檔案、HEAD、尚未推送提交與 origin/main。需要整合前先備份或 stash 保留全部既有工作；執行 git fetch origin main 並讀取最新 AGENTS.md。乾淨工作樹只落後時正常 fast-forward；有雙方獨立提交時正常 merge，保留各方改動並處理衝突，不重置、丟棄或強制覆寫遠端。

3. 執行 AGENTS.md 要求的 node scripts/check-workspace.mjs，分開判讀 Git 與匿名 HTTP 結果。若只有正式站 HTTP／CONNECT 受阻或環境設定不符，保留真實診斷與既有問題，Git 同步獨立繼續；不要把正式站 403 當成 Git 推送失敗，也不自行改網路或發布環境。

4. 需要整合其他對話或 Sites 工作時，同時核對 .openai/hosting.json 指向的既有 Sites 原始碼分支，正常合併尚未納入的提交，保留各方內容。只對本次可存取的檔案與提交回報結果；其他隔離工作的未提交草稿無法透過 Git 取得，不宣稱已納入。

5. 對實際改動執行適用的既有檢查；文件變更檢查差異與本機連結，程式或資料變更驗證受影響功能，未受影響且已通過的檢查不反覆重跑。可安全修復與本任務直接相關的同步問題後重驗，未執行的測試不得宣稱通過。

6. 檢查通過後建立清楚的 commit；已有未推送提交也要處理。每個新修改步驟前、提交前及 push 前再次 fetch；有並行更新時先保存工作、正常整合並重驗受影響內容，再執行 git push origin HEAD:main。推送後以 git ls-remote origin refs/heads/main 讀回遠端 SHA 確認結果，不只依賴本機參考或 push 文字。

7. 沒有實際改動時不建立空提交。若純唯讀核對後沒有待同步內容且沒有 Git 同步錯誤，不為產生提交而新增或修改 log.md／Issue.md，也不另通知；這是本專責工作的紀錄例外。實際整合、修正、提交、推送或遇到錯誤時，依專案規則更新 log.md 與 Issue.md。

8. 工作目錄不存在、環境不可用、適用檢查失敗、未解合併衝突、權限或推送失敗時保留所有工作，回報發生步驟、實際錯誤、受影響檔案或提交、尚未推送內容與下一個處理方法。尚未確認遠端成功前不能宣稱完成。

9. 成功推送時以繁體中文簡短回報 commit、主要變更與驗證範圍；有新錯誤或仍未解決的 Git 同步錯誤時通知使用者，並區分 Git 與正式網站的限制。不要要求使用者在其他對話間反覆搬運可自行查得的版本或環境資訊。

10. 本工作只負責 Git 同步與錯誤回報；網站及環境發布由既有整合窗口另行處理，正式登入保存、跨裝置與還原驗收另依使用者明確指示執行。不得改動或清空正式個人學習資料；HTTP 200 不等於上述功能已驗收。不得輸出或提交密碼、Cookie、權杖、個人學習紀錄或含識別資料的臨時交接檔。
