## 每個對話都從GitHub最新來源工作

1. 開始每次工作、收到新變更指示，以及長時間工作後準備下一個步驟時，先檢查 `git status --short --branch`、遠端位址與HEAD。保留未提交及未追蹤內容；整合前需要時備份或stash，不重置、丟棄或用舊快照覆蓋。
2. 執行 `git fetch origin main`，讀取最新工作規則（必要時先用 `git show origin/main:AGENTS.md`）。新工作以最新 `origin/main` 為基礎，不以對話記憶、下載交接包或環境快照當成最新程式。
3. 乾淨工作樹若只落後遠端，使用 `git merge --ff-only origin/main`。本機已有獨立提交時正常merge，解決衝突並完整保留雙方內容；未提交工作先妥善保存，再還原／整合。不要強制推送。
4. 每完成一個可獨立提交的修改，執行適用檢查、立即commit。推送前再fetch，遠端有新提交則先正常整合並重驗受影響內容，執行 `git push origin HEAD:main`，再以 `git ls-remote origin refs/heads/main` 核對結果。
5. push因另一對話先推送而失敗時，保留本機提交，fetch／merge／檢查後再推送，不要求使用者重做整輪，也不覆寫遠端。回報實際commit及尚未成功的部分。
6. 記錄實際完成與未完成項目於log、Issue與todo。不同對話使用明確的工作標題與唯一編號，遇重複編號保留銜接註記。檢查／建立新編號前先讀最新清單。

Git同步的是已commit並push的內容。其他對話須fetch並整合後才看得到；未提交的草稿、執行中的程序與瀏覽器工作階段不會即時互通。本規則不建立自動背景輪詢，不承諾正在執行的對話會即時重讀規則。

## 發布與工作階段

- GitHub來源、Sites來源及正式部署分別核對。GitHub push不等於部署；需要發布時使用同一來源SHA，核對原站點、現有D1、存取設定及實際部署結果。遵守使用者在該對話的當次指示，明確「不發布」優先於一般預設授權。
- 環境快照可以提供依賴，但程式以GitHub最新來源為準；不要重套舊對話修改。
- 網路政策、憑證、密碼、登入Cookie與本機學習快取不由Git同步。每個工作階段核對自己的environment_id、實際規則及正式網址連線；不能把另一環境的200或403套用到本環境。
- 網域參考見[目前網路參考](cloud-environment/network-reference.json)。先讀目標環境既有設定，保留既有允許項目；不要因歷史檔寫restricted就把目前unrestricted改回受限。
- 使用者學習資料由原正式DB及同帳號同步維護，不是Git程式檔。切換網址、更新來源或調整工作流程不代表移轉／清除個人資料；資料清空仍依獨立要求與核對程序處理。
